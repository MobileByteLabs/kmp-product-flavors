# v2.4 Beta Testing Guide

One-page guide for piloting `kmp-product-flavors` `2.4.0-beta.N` on your real consumer project.

**Why this exists**: `v2.4.0` GA promotion is gated on **≥2 external adopter reports of "clean ≥1 week"** soak time. Without that signal, the plugin can't graduate from "looks stable" to "is stable". Your report is one of the gates.

---

## What's in v2.4

The full Added / Fixed / Stable / Experimental / Workaround surface ships in [`CHANGELOG.md [2.4.0]`](../CHANGELOG.md). Highlights:

- **Per-variant publishing** with classifier-tagged Maven artefacts (JVM, iOS XCFramework, JS, WasmJs, npm). Snapshot channel live on Sonatype.
- **Matrix mode** (`buildMatrix.set(true)`) — compile every variant on every target in one Gradle invocation. The default when `autoEnable=true` (v2.2+) and conditions match.
- **Variant-conditional dependency excludes** — strip a dep from one variant's classpath only.
- **Detekt per (variant × target)** — per-target baselines so `commonPaid` symbols can have different rules on iOS vs Desktop.
- **Variant-scoped Gradle build-cache namespacing** — opt-in; default flip waits on real cache-hit telemetry.
- **Compose hot-reload Option A** — `./gradlew switchVariantAndReload --to=<variant>` (daemon-restart-based workaround; Option B graduates when CMP exposes a public reset API).
- **23 structured validator codes** (`KMPF-V01` … `KMPF-V23`) with severity + actionable fix + auto-suggested renames.
- **AGP bridge** — `kmpFlavors.flavors { … }` and `kmpFlavors.buildTypes { … }` forward into Android's `productFlavors { … }` and `buildTypes { … }` automatically.

## How to pin a beta

```kotlin
// gradle/libs.versions.toml
[versions]
kmpProductFlavors = "2.4.0-beta.0"   // or 2.4.0-beta.N / 2.4.0-rc.N as they ship

[plugins]
kmp-product-flavors = { id = "io.github.mobilebytelabs.kmp-product-flavors", version.ref = "kmpProductFlavors" }
```

```kotlin
// build.gradle.kts
plugins {
    kotlin("multiplatform")
    alias(libs.plugins.kmp-product-flavors)
}
```

If you want to track the unreleased HEAD instead of a tagged beta, see [`docs/PUBLISHING.md` → Snapshot channel](PUBLISHING.md#snapshot-channel-v23). Snapshots are republished nightly at 03:00 UTC.

Fresh adopters: read [`docs/QUICKSTART.md`](QUICKSTART.md) (5 min) before pinning. Migrating from `v1.x`: read [`docs/MIGRATION_v1_to_v2.md`](MIGRATION_v1_to_v2.md) first — `activeFlavor.set("name")` no longer works; the v1.x compat shim is removed on **2026-11-14**.

## What to exercise

Cover the paths your real project uses. The structured report ([Beta Stability Report issue template](https://github.com/MobileByteLabs/kmp-product-flavors/issues/new?template=v2.4-beta-stability-report.yml)) asks you to tick which v2.4 features you actively touched.

Minimum baseline (for the soak to count):

1. **Clean build from cold cache** — `./gradlew clean assemble` against your full target list. No regressions vs the previous plugin pin you were on.
2. **At least one variant switch** — change the active variant via `-PkmpFlavor=<variant>` or `isDefault.set(true)` and re-build. No surprise `BuildKonfig` content.
3. **Matrix mode if applicable** — if you have ≥2 flavors and ≥2 non-Android targets, run `./gradlew :module:assembleAllVariants` and confirm every inactive variant compiles.
4. **One full CI cycle** — let your daily CI build the beta-pinned tree end-to-end for ≥7 calendar days. Note any cost / time changes.

Optional but very valuable:

- **Per-variant publishing roundtrip** — if you publish per-variant artefacts (Maven Central or local), confirm consumers resolve via the variant classifier (e.g. `coordinate:1.0.0:freeRelease`).
- **Variant-conditional dep exclude** — register an `exclude(group, module)` on a `variants.matching { … }` block and assert the dep is absent from that variant's `compileClasspath` only.
- **Compose hot-reload smoke** — `./gradlew switchVariantAndReload --to=<variant>` and follow the printed instructions.
- **IDE plugin v0.2 EAP** — install from JetBrains Marketplace `eap` channel and report whether gutter icons / variant-aware refactor / breakpoint scoping behave on your project.

## What to look for (red flags)

| Signal | What it means |
|---|---|
| Any `KMPF-V<NN>` ERROR | Structured validator finding. Cross-ref [`docs/ERROR_CODES.md`](ERROR_CODES.md). Report the code + your fix. |
| Kotlin "Conflicting declarations: const val …" in generated `BuildKonfig.kt` | Likely a `KMPF-V23`-class collision the validator should have caught. **High-priority blocker** — please report. |
| "Invalid Source Set Dependency Across Trees" warning from KGP | Cosmetic; documented in `RFC §10`. Not a blocker unless it causes a real compile failure. |
| `Gradle daemon restart required after variant switch` | Expected for Option A Compose hot-reload. Option B is CMP-API-WAITING (Issue #75). |
| Cache-miss explosion after enabling `variantCacheNamespacing` | Expected — the feature ships opt-in and the default-flip waits on telemetry. If you have Build Scan data, please attach it. |
| Anything else surprising | Worth reporting in the structured form. |

## How to report

Use the **[v2.4 Beta Stability Report](https://github.com/MobileByteLabs/kmp-product-flavors/issues/new?template=v2.4-beta-stability-report.yml)** issue template. It captures:

- Plugin version under test + soak duration
- Overall outcome (✅ / 🟡 / 🔴)
- Tooling versions (KGP, CMP, AGP, Gradle)
- Project shape (flavor × build-type × target counts, module count)
- Which v2.4 features you exercised
- DSL friction / docs gaps
- Validator codes that fired
- Blocker details (if 🔴)
- GA changelog credit preference

The report itself takes ~10 min to fill once the soak window has passed.
